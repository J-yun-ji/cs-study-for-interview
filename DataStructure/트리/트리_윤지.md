### ✏️  트리

- **트리(tree)란 ?**
    - 데이터가 저장되어 있는 **노드**, 노드와 노드를 연결하는 **간선(edge or link)** 으로 이루어져 있는 계층적인 구조를 표현하기 위한 자료구조
- 부모 노드는 하나만, 자식 노드는 하나 이상

**트리와 관련한 용어**

| **노드(node)** | 트리 자료구조에서 데이터를 저장하는 구성 요소 |
| --- | --- |
| **간선(edge)** | 트리 자료구조에서 노드를 연결하는 구성 요소 |
| **부모 노드(parent node)** | 어떤 노드의 상위에 연결된 노드 |
| **자식 노드(child node)** | 어떤 노드의 하위에 연결된 노드 |
| **형제 노드(sibling node)** | 같은 부모 노드를 공유하는 노드 |
| **조상 노드(ancestor node)** | 부모 노드와 그 부모 노드들 |
| **자손 노드(descendant node)** | 자식 노드와 그 자식 노드들 |
| **루트 노드(root node)** | 트리의 최상단 노드, 부모 노드가 없는 노드 |
| **리프 노드(leaf node)** | 트리의 최하단 노드, 자식 노드가 없는 노드 |
| **차수(degree)** | 어떤 노드가 가지고 있는 자식 노드의 수 |
| **레벨(level)** | 루트 노드에서 시작해 특정 노드에 이르기까지 거치게 되는 간선의 수, 깊이(depth)와 같은 개념 |
| **높이(height)** | 트리의 가장 높은 레벨 |
| **서브트리(subtree)** | 트리에 포함되어 있는 부분 트리 |
- 하나의 노드를 데이터를 저장할 공간, 자식 노드의 위치 정보를 저장한 공간들의 모임이라 간주하면 됨

### ✏️ 트리의 순회

- **트리의 순회(tree traversal)란 ?**
    
    → 트리의 모든 노드를 한 번씩 방문하는 것
    

**트리의 순회 방법 3가지**

![734373CB-8237-4252-84D0-AD836B4B8258](https://github.com/user-attachments/assets/fad9ba84-8deb-4e7d-8768-631d484a3f82)


[트리 그림]

1. **전위 순회(preorder traversal)** 
    - **루트 노드 → 왼쪽 서브트리 전위 순회 → 오른쪽 서브트리 전위 순회**
    - 위 트리 방문 결과 : **a → b → d → h → i → e → j → k → c → f → l → g**
    - 전위 순회에 대한 **의사 코드(presudo code)**
        
        ```jsx
        전위 순회(노드) :
        	if 노드가 존재하지 않으면 :
        		return 
        	노드 값 출력
        	전위 순회(노드의 왼쪽 자식)
        	전위 순회(노드의 오른쪽 자식)
        ```
        
2. **중위 순회(inorder traversal)**
    - **왼쪽 서브트리 중위 순회 → 루트 노드 → 오른쪽 서브트리 중위 순회**
    - 위 트리 방문 결과 : **h → d → i → b → j → e → k → a → l → f → c → g**
    - 중위 순회에 대한 **의사 코드(presudo code)**
        
        ```jsx
        중위 순회(노드) :
        	if 노드가 존재하지 않으면 :
        		return 
        	중위 순회(노드의 왼쪽 자식)
        	노드 값 출력
        	중위 순회(노드의 오른쪽 자식)
        ```
        
3. **후위 순회(postorder traversal)**
    - **왼쪽 서브트리 후위 순회 → 오른쪽 서브트리 후위 순회 → 루트 노드**
    - 위 트리 방문 결과 : **h → i → d → j → k → e → b → l → f → g → c → a**
    - 후위 순회에 대한 **의사 코드(presudo code)**
        
        ```jsx
        후위 순회(노드) :
        	if 노드가 존재하지 않으면 :
        		return 
        	후위 순회(노드의 왼쪽 자식)
        	후위 순회(노드의 오른쪽 자식)
        	노드 값 출력
        ```
        
- **레벨 순서 순회(level-order traversal)**
    - 가장 낮은 레벨부터 차례대로 노드를 순회하는 방법
    - 위 트리 방문 결과 : **a → b → c → d → e → f → g → h → i → j → k → l**

### ✏️ 트리의 종류

- **이진 트리(binary tree)**
    
    → 자식 노드의 개수가 2개 이하인 트리
    
    - 대중적인 트리
    
    ![8BDFA380-6BD0-4FF4-AF5A-BF7702D04BD8](https://github.com/user-attachments/assets/c93c6279-e8bf-40cd-82bf-4eda762a4bef)

    
- **편향된 이진 트리(skewed binary tree)**
    
    → 모든 자식 노드가 한 쪽으로 치우진 이진 트리
    
    ![C078C48C-F3B4-4791-B8B0-B6F2D3E021F1](https://github.com/user-attachments/assets/862c00f9-7366-4355-b1ef-995f1fd05b8a)

    
- **정 이진 트리(full binary tree)**
    
    → 자식 노드의 개수가 0개 또는 2개인 이진 트리
    
    ![C73BD870-D864-435B-9AE4-2DE38D7833F0](https://github.com/user-attachments/assets/a0d23cb9-b14f-49da-87d1-f93bbdc99f21)
    
- **포화 이진 트리(perfect binary tree)**
    
    → 리프 노드를 제외한 모든 노드들이 자식 노드를 2개씩 가지고 모든 리프 노드의 레벨이 동일한 이진 트리
    
    ![112E3F95-A7A3-4642-AB6B-691B6ED87636](https://github.com/user-attachments/assets/215b5db8-8a0e-4f39-a2fa-713c05300aa0)

    
- **완전 이진 트리(complete binary tree)**
    
    → 마지막 레벨을 제외한 모든 레벨이 2개의 자식 노드를 가지고 있고 마지막 레벨의 모든 노드들이 왼쪽부터 존재하는 이진 트리

**탐색에 활용되는 트리 : 이진 탐색 트리와 힙**

- **이진 탐색 트리(BST, B**inary **S**earch **T**ree**)란 ?**
    
    → 특정 노드의 왼쪽에는 해당 노드보다 작은 값, 오른쪽에는 해당 노드보다 큰 값이 있는 트리
    
    - O(log n)으로 원하는 값 탐색 가능
    
    ![AE1848BD-F0C9-40D6-B7A4-2F7BA1E91520](https://github.com/user-attachments/assets/8201f552-532d-4f25-90c6-8b8b2d363dd0)
    
    - 편향된 이진 트리의 경우 탐색 속도는 O(n)
        - 최악의 상황임
- **힙(heap)이란 ?**
    
    → 최댓값과 최솟값을 빠르게 찾기 위해 사용하는 탐색에 특화된 이진 트리의 일종
    
    - **최대 힙**
        
        → 부모 노드가 자식 노드의 값보다 큰 값으로 이루어진 이진 트리
        
    - **최소 힙**
        
        → 부모 노드가 자식 노드의 값보다 작은 값으로 이루어진 이진 트리
        
        ![힙](https://github.com/user-attachments/assets/ce6c378c-ba12-4914-96dc-496de8b1c140)
        
- 최대 힙을 구현하면 최상단 루트 노드는 언제나 우선순위가 가장 높은 값을 가짐
    - 큐의 원리
    - 우선순위 큐는 최대 힙으로 구현 가능

**균형을 맞추는 트리 : RB 트리**

- 이진 탐색 트리의 한 가지 **문제점**
    
    → 삽입, 삭제 연산을 반복하는 과정에서 트리가 한 쪽으로만 자라는 편향된 트리가 될 수 있다는 것
    
    - O(n)으로 연결리스트와 다를 바 없고 트리를 사용할 이유가 사라지게 됨
- **자가 균형 이진 탐색 트리(self-balancing binary search tree)**
    
    → 왼쪽 서브트리와 오른쪽 서브트리 높이의 균형을 맞추는 이진 탐색 트리
    
    - **ALV 트리(Adelson-Velsky and Landis Tree)**
    - **RB 트리(Red Black Tree)**
        
        → 노드에 색을 칠하는 규칙과 노드에 칠해진 색을 기준으로 왼쪽 서브트리 높이와 오른쪽 서브트리 높이의 균형을 맞추는 트리
        
    - **RB 트리 유지 조건**
        1. 루트 노드는 블랙 노드이다.
        2. 리프 노드는 블랙 노드이다.
        3. 레드 노드의 자식 노드는 블랙 노드이다.
        4. 루트 노드에서 임의의 리프 노드에 이르는 경로의 블랙 노드 수는 같다.

**대용량 입출력을 위한 트리 : B 트리**

- **B 트리란 ?**
    
    → 균형을 유지하는 트리 중 하나로, 이진 탐색 트리가 아닌 다진 탐색 트리의 한 종류
    
    - **다진 탐색 트리** : 한 노드가 여러 자식 노드를 가질 수 있는 트리
- **M차 B 트리**
    
    → 한 노드가 가질 수 있는 최대 자식 노드의 개수가 M개인 B트리
    
    - 루트, 리프 노드를 제외하고 가질 수 있는 최소 자식 노드의 개수는 [M/2]개
    - ex. 5차 B 트리의 한 노드는 최대 5개를 3차 B 트리는 최대 3개.
- B 트리의 각 노드에는 하나 이상의 키 값 존재, 각 키들은 오름차순으로 저장
- 키가 N개인 노드가 가질 수 있는 자식 노드의 수는 반드시 (N + 1)개가 됨
    
    → 키 사이 사이에 자식 노드가 존재하기 때문
    
- B 트리는 모든 리프 노드의 깊이가 같음
    
    → 특정 노드에만 자식 노드가 존재하는 편향된 상태는 X

## 📈 추가 학습 필요

### **힙 사용 이유 ?**

- 최솟값 or 최댓값을 찾기 위해 배열을 사용하면 **Ο(n)** 만큼 걸림
    
    → 힙 사용 시 **O(log n)** 만큼 소요되므로, 배열을 사용할 때보다 빠르게 구할 수 있음
    
- 우선순위 큐와 같이 최댓값 또는 최솟값을 빠르게 찾아야하는 알고리즘 등에 활용

### 힙의 조건

1. 힙은 **최대힙(Max heap)** 과 **최소힙(Min heap)** 으로 나뉘어진다. 최대힙은 자식 노드보다 부모 노드의 값이 크고, 최소힙은 자식 노드보다 부모 노드의 값이 작다.
2. 노드가 왼쪽부터 채워지는 **완전 이진 트리** 형태를 가진다.
3. 중복을 허용한다.
